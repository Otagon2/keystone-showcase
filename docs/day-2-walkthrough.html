03 The research

We used Arize & Braintrust for real

Before designing, I ran Zaki’s exact loop end-to-end on both reference tools with the same GST dataset — importing data, writing a prompt, building an evaluator, running an experiment, and drilling into traces — and mapped every interaction. The full teardown (UX reports, interaction maps, side-by-side comparison) is in the competitor doc.

Braintrust

The strongest reference — excellent experiment → trace linkage and column-mapping on import. But the playground is ephemeral (a run vanishes until you promote it), scorer setup is painful, and you wait for the whole run before seeing anything.

✓ copy summary + trace linkage, column mapping
✗ avoid ephemeral playground, painful scorers, no streaming

Arize Phoenix

Deep and capable, but dense and developer-first. The dataset import is a multi-step schema mapping, the summary is buried under raw tables, and the trace drill-down is hard to find — the opposite of summary-first.

✓ copy rich experiment metrics, span detail
✗ avoid density, buried traces, table-first defaults
04 Design principles

The rules we set — and followed on every screen

Summary-first, always
Every results view opens on the scorecard, not a raw table. Zaki’s #1 principle — and where both competitors fail.
Teach the loop by walking it
The IA is the loop (Build · Evaluate · Observe). A first-timer learns eval by navigating; a veteran moves fast.
Honest numbers only
The repo has no cost concept — so we show token-spend, never a fabricated dollar figure.
Ground every pixel in the repo
Real entities, real fields, and full ks CLI parity. Divergences from the shipped app are deliberate and flagged.
Flat over drawers
Centered dialogs and inline flows, not the shipped side-drawers. Fewer places to get lost.
Accessible & responsive by default
Status by icon-shape (not colour alone), dark + light both shipped, usable down to 390px.
05 Decisions & why

The calls that make it Keystone

Token-spend, never dollars
Why: the repo tracks only tokens. Dollar figures would be invented — a credibility risk with an ex-Arize/Braintrust reviewer. We lead with token-spend + latency.
Single-brace {question}
Why: matches the shipped parser /\{(\w+)\}/. The brief’s {{mustache}} would break at runtime.
Dark leads, light co-equal
Why: a developer console reads dark-first; but light is fully built and AA-checked, toggled from the header.
shadcn New York + slate
Why: read from the repo’s own components (button geometry, lucide, indigo removed). Calm monochrome; green/red only for pass/fail.
Evaluator is first-class
Why: “how is my output judged” is the heart of the loop. We designed it as a real, reusable object and flagged the backend binding (⚑).
One run, capturable
Why: Braintrust’s ephemeral playground loses work. Our live-test run is capturable and promotable to a tracked experiment.

Every decision is logged with before/after reasoning in the design review.

07 Screen-by-screen walkthrough

Every page, and why it’s designed that way

Expand any screen for its shot, the design decisions, and how it beats Arize & Braintrust. (This is the same content as the in-app “Why this design?” button.)

01Overview — the loop, learnable/#/

Design decisions

  • Loop-as-onboarding: a 5-step checklist (Build · Evaluate · Observe).
  • Summary-first: progress + the next action up top.
  • Secrets never render — “Your API key stays hidden”.

Better than Arize & Braintrust

  • They drop you in an empty dashboard; we teach the loop by walking it.
  • Honest token framing, never a fake $ cost.
02Prompts — the versioned library/#/prompts

Design decisions

  • Run status by icon shape (WCAG), not colour alone.
  • Version, env dot, labels, last-run all visible.
  • Row → Edit; hover-Run; ⋯ menu to govern.

Better than Arize & Braintrust

  • A real library with env + version; competitors bury versioning.
  • Token-spend column, never a made-up dollar figure.
03Edit — write & try in one place/#/prompts/gst-qna

Design decisions

  • Single-brace {question} — matches the shipped parser.
  • Live test: tokens + latency (no cost) + Capture.
  • Inspector: output type, inputs, references, token budget.

Better than Arize & Braintrust

  • Braintrust’s playground is ephemeral; ours is capturable + promotable.
  • One surface: write → try → “Run as an experiment →”.
04Run — batch over the dataset/#/prompts/gst-qna/run

Design decisions

  • Rows stream in as they finish.
  • Temporary until promoted to a tracked experiment.
  • Token-spend + latency per row.

Better than Arize & Braintrust

  • Braintrust makes you wait for the whole run; ours streams.
  • A clear ephemeral → tracked seam.
05Compress — trim tokens, keep behaviour/#/prompts/gst-qna/compress

Design decisions

  • Greyed = removed (with a legend), not struck.
  • Token savings shown (1,240 → 890, 28%).
  • LLMLingua backend flagged as a fast-follow (⚑).

Better than Arize & Braintrust

  • Neither competitor offers prompt compression with token economics.
06Manage — versions, envs, people/#/prompts/gst-qna/manage

Design decisions

  • Promote disabled when already in production (tooltip why).
  • Owner static; members removable; roles as selects.
  • Delete gated by type-to-confirm.

Better than Arize & Braintrust

  • Governance is first-class + summary-first, not buried in settings.
07Dataset — the test set/#/datasets

Design decisions

  • Column mapping set once at import (input/expected/metadata).
  • One standard dataset template across the loop.

Better than Arize & Braintrust

  • Arize’s import is dense + multi-step; ours is a single mapping.
08Evaluator — how answers are scored/#/evaluators

Design decisions

  • Evaluator is a first-class, reusable object (⚑ backend flagged).
  • Variables mapped once (input/output/expected).
  • Live test shows verdict + reasoning + token-spend.

Better than Arize & Braintrust

  • Braintrust’s scorer setup is painful; ours is a template + live test.
  • Decoupled evaluators, reusable across experiments.
09Experiment — the scorecard/#/experiments/7

Design decisions

  • Summary-first: 83% pass + distribution before the table.
  • Token-spend + latency tiles (no $).
  • Any row → its own trace in one click.

Better than Arize & Braintrust

  • Summary-first by default — competitors open on a raw table.
  • One-click experiment → trace linkage.
10Trace — the drill-down/#/traces/gst-003

Design decisions

  • Token chip + reconciling span totals (no $).
  • Reasoning / Messages / Raw JSON tabs.
  • Every row opens its own trace.

Better than Arize & Braintrust

  • Braintrust’s link is good; Arize buries it — ours is one click.
  • The evaluator’s reasoning is front-and-centre.
11States & edge cases/#/states

Design decisions

  • Empty states with one clear call-to-action.
  • A streaming “running” progress state.
  • Errored rows show n/a + the reason (429), never a silent blank.

Better than Arize & Braintrust

  • They under-design these; we make them first-class.
12Responsive + in-app guideany width

Design decisions

  • Usable to 390px: rail → hamburger sheet, panes stack, tables → cards.
  • ⌘K, loop ribbon and summary-first are identical at every width.

Better than Arize & Braintrust

  • Both are effectively unusable below ~1000px.
  • The in-app guide explains our thinking as you click — no doc-hunting.
