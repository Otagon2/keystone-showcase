# Keystone — documentation at a glance

*One screen to orient anyone who lands here. This is the design documentation behind **Keystone** (Esberi's AI platform) — the four clickable prototypes built for Zaki's GitHub issues, plus the research, briefs, and audit trail behind them. Everything is shadcn/ui **New York**, dark developer-console theme. Last updated 3 Jul 2026.*

## What was delivered

Four self-contained, clickable HTML prototypes — one per GitHub issue — and the thinking that produced them:

- **#1 Prompt Management** — write → try → batch → compare → compress → govern, without leaving the surface.
- **#2 Organization Admin** — org-scope governance: members & roles, projects, write-once secrets, connections, billing, audit.
- **#3 Inbox** — a cross-project feed + task queue where notifications clear by *reading* and tasks clear only by *acting*.
- **#4 System Admin** — the platform control plane and the audited "Enter-org" assume-role.

All four share one visual + interaction contract; all were carried through six rounds of audit. The prototypes themselves are on the [home page](index.html); the documents below are the record behind them.

## How these docs are organised

- **Overview** — this page, plus the **engagement report**: the full narrative — every deliverable, the 7 design principles, and each decision with its rationale.
- **Research & decisions** — how the work was grounded: the **domain guide** (prompt management from zero + a ~120-term glossary), the **gap analysis** (what the client's contract wanted vs the original plan), the **shadcn New York spec**, the **execution plan**, and the six-round **audit notes**.
- **The briefs (specs)** — the source of truth per surface: the four issue briefs, the binding **style contract**, and the **redesign brief**.
- **GitHub** — the ready-to-paste replies to issues #1–#4, with the open questions for the backend team.

## How to read it, by why you're here

- **New to the project** → start with the **engagement report** for the story, skim the **domain guide** if prompt management is unfamiliar, then open any **brief** next to its prototype.
- **Reviewing the design** → the **audit notes** and **shadcn New York spec** show the quality bar and the New-York fidelity rules.
- **Wiring the backend** → go straight to the **GitHub comment drafts** for the open questions that need product answers.
