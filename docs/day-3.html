GitHub update · Day 3 — Datasets to PRD #5

Ready to post on issue #5: the Dataset surface is clickable end-to-end, with the decisions to ratify and the open naming questions.

#5Dataset Management → clickable to the appendicesClickable prototype

The full Dataset surface is walkable — list (stats bar · filters · Display columns · bulk · full row ⋯) · create (Upload CSV with a drag-to-bucket mapper · via skill · via code: CLI/TS/Python/REST + Create API key) · editor frame (Items · Versions · Experiments · Manage pills) · working draft → Save version · tags as movable version pointers (golden → v3) · provenance + Origin backlinks · experiments that pin a version.

Decisions to ratify
  • Human version numbers with change notes — not txids (Braintrust) or timestamps (Arize).
  • Mapper accessibility — drag-to-bucket plus a per-column menu, so import works by keyboard/touch.
  • Type-name-to-confirm delete per the PRD — stricter than either competitor.
Open naming questions
  • CLI/SDK names (@keystone-ai/cli, keystone_ai), api.keystone.dev, key format ks_live_… — all invented for the mock.
  • Skill install path (npx skills add esberi/keystone-skills) — confirm the org/repo.
