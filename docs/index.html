#3InboxPrototype ready

The load-bearing rule is enforced in code, not just drawn: informational = read-to-clear, actionable = act-to-clear (mark-read never touches an actionable). Deciding resolves in place — the item leaves Needs-action, stays in All with an outcome chip, and the account-block badge decrements live.

  • Needs-action sorts by urgency; All is reverse-chronological.
  • One approval auto-resolves ~20s after you open the Inbox ("Resolved by another approver") — the first-decision-wins / no-zombie-tasks property, demonstrated. An expired approval shows "expired · missed".
Deferred exactly per your non-goals
  • Preferences/channels, bulk approve, threads, grouping/digests.

#4System AdminPrototype ready

The control plane with the tenant boundary enforced: three operator surfaces (Organizations · Platform Settings · Platform Audit), no project shell. Org lifecycle with guarded actions — Delete disabled until suspended, resend-invite only while pending-setup.

  • Enter org (the showpiece): re-auth → "you'll act as an administrator; this session is audited" → the shell switches to that org's Admin under a persistent banner. The northwind "no reachable admin" recovery journey works end-to-end.
  • Delete is guarded: suspend-first → re-auth → type-the-name with blast radius → 30-day soft window + Restore. Platform Audit highlights operator.* rows — the "prove isolation" view.
